# Terraform: Инфраструктура для NFS и MinIO

Этот раздел проекта создает виртуальные машины в Yandex Cloud с помощью **Terraform**. Ниже описано, как устроен код, какие файлы за что отвечают и как запустить создание инфраструктуры.

## 📂 Структура папки `infra/`

```text
infra/
├── main.tf                  # Основной код: создание сети, ВМ, группы безопасности
├── variables.tf             # Объявление переменных (что можно менять)
├── outputs.tf               # Вывод IP-адресов после создания
├── providers.tf             # Настройка провайдера Yandex Cloud
├── terraform.tfvars.example # Шаблон для заполнения переменных
├── terraform.tfvars         # Реальные значения (не в Git!)
└── key.json                 # Ключ сервисного аккаунта (не в Git!)
```

## 📝 Описание файлов и переменных

### 1. `variables.tf` — Переменные
Здесь объявлены параметры, которые можно изменять без правки основного кода конфигурации.

| Переменная       | Тип        | Описание                                                                                    |
| :--------------- | :--------- | :------------------------------------------------------------------------------------------ |
| `cloud_id`       | `string`   | ID вашего облака в Yandex Cloud.                                                            |
| `folder_id`      | `string`   | ID вашего каталога.                                                                         |
| `ssh_public_key` | `string`   | Публичный SSH-ключ для доступа к ВМ.                                                        |
| `zone`           | `string`   | Зона доступности (по умолчанию `ru-central1-d`).                                            |
| `serv_configs`   | `map(any)` | Карта с индивидуальными настройками для каждой ВМ (имя, CPU, RAM, размер диска, ID образа). |

### 2. `main.tf` — Создание ресурсов
Этот файл описывает целевое состояние инфраструктуры в облаке:

*   **`yandex_compute_disk.boot_disk`** — создает загрузочные диски для каждой ВМ. Использует цикл `for_each = var.serv_configs`, чтобы сгенерировать точное количество дисков по числу хостов в карте.
*   **`yandex_vpc_network.network-vm`** — инициализирует изолированную виртуальную сеть.
*   **`yandex_vpc_subnet.subnet-vm`** — разворачивает подсеть `192.168.10.0/24` внутри зоны `ru-central1-d`.
*   **`yandex_compute_instance.serv_config`** — создает виртуальные машины. Использует `platform_id = "standard-v2"` (так как v1 не поддерживается в зоне d) и `core_fraction = 20` для экономии квот. Автоматически привязывает ранее созданные диски через `disk_id`.
*   **`yandex_vpc_security_group.sg_vm`** — настраивает файрвол (Security Group), открывая порты доступа: `22` (SSH), `80` (Nginx), `9000` (MinIO API/Консоль), `2049` (NFS).

### 3. `outputs.tf` — Результаты выполнения
После завершения процесса сборки Terraform возвращает полезные данные:

*   **`vm_nat_ip`** — выводит внешние (публичные) IP-адреса для каждой ВМ. Полученные значения необходимо перенести в настройки Ansible.

### 4. `terraform.tfvars.example` — Шаблон переменных
Пример того, как должен выглядеть файл `terraform.tfvars`. Скопируйте его и заполните своими значениями. Сам файл `terraform.tfvars` гарантированно исключен из Git через `.gitignore`, чтобы не светить ваши секреты.

Пример структуры:
```hcl
cloud_id       = "b1g..."
folder_id      = "b1g..."
ssh_public_key = "ssh-ed25519 ..."
serv_configs   = { ... }
```

### 5. `key.json` — Ключ авторизации
Файл авторизации сервисного аккаунта Yandex Cloud. **Ни в коем случае не отправляйте его в публичный репозиторий!**

## 🚀 Как запустить

1.  **Настройте авторизацию:** Получите JSON-ключ вашего сервисного аккаунта Yandex Cloud и сохраните его в папку `infra/` под именем `key.json`.
2.  **Подготовьте переменные:** Скопируйте шаблон окуржения и укажите свои рабочие ID и ключи:
    ```bash
    cp terraform.tfvars.example terraform.tfvars
    nano terraform.tfvars
    ```
3.  **Разверните инфраструктуру:** Выполните инициализацию провайдера и примените конфигурацию:
    ```bash
    terraform init
    terraform apply
    ```
4.  **Сохраните IP-адреса:** Скопируйте список адресов из блока `vm_nat_ip` — они потребуются для заполнения файла `inventory.ini` в Ansible.

## ⚠️ Возможные ошибки и их решение

*   **`Platform standard-v1 is unavailable`**
    *   *Решение:* В `main.tf` жестко установлена платформа нового поколения `platform_id = "standard-v2"`. Убедитесь, что вы случайно не изменили эту строчку.
*   **`Quota limit exceeded`**
    *   *Решение:* Превышены лимиты вашего облачного каталога. Уменьшите параметры `disk` или `vm_cpu` внутри `terraform.tfvars` и повторите попытку.
*   **`State lock / Зависание стейта`**
    *   *Решение:* Если процесс Terraform был прерван некорректно, перезапустите терминал окружения WSL через `wsl --shutdown` или вручную завершите зависший процесс командой `kill -9 <PID>`.
