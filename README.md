# nfs-objstorage

# NFS и объектное хранилище MinIO в Yandex Cloud

Этот репозиторий содержит код для автоматизированного развертывания инфраструктуры и настройки сервисов хранения данных. Проект демонстрирует подход **Infrastructure as Code (IaC)** и использование **Configuration Management**.

## 🏗️ Архитектура и стек технологий

*   **Инфраструктура (Terraform):**
    *   Создание виртуальных машин в Yandex Cloud.
    *   Настройка виртуальной сети (VPC) и подсетей.
    *   Настройка групп безопасности (Security Groups) для доступа по SSH, NFS и HTTP.
    *   Генерация SSH-ключей и передача их через `cloud-init` (metadata).
*   **Конфигурация (Ansible):**
    *   Установка и настройка NFS-сервера (файловое хранилище).
    *   Настройка NFS-клиента (монтирование директорий).
    *   Установка и настройка MinIO (объектное хранилище, S3-совместимое).
    *   Установка и настройка Nginx (прокси-сервер для доступа к MinIO).

## 🚀 Быстрый старт

### 1. Развертывание инфраструктуры (Terraform)

```bash
cd infrastructure
cp terraform.tfvars.example terraform.tfvars

# Заполните terraform.tfvars (cloud_id, folder_id, ssh_public_key)
nano terraform.tfvars

terraform init
terraform apply
```
После успешного применения Terraform выведет публичные IP-адреса серверов.

### 2. Настройка сервисов (Ansible)

```bash
cd ../ansible
cp inventory.example.ini inventory.ini

# Впишите IP-адреса из вывода Terraform в inventory.ini
nano inventory.ini

# Настройка NFS
ansible-playbook -i inventory.ini playbooks/nfs.yml

# Настройка MinIO
ansible-playbook -i inventory.ini playbooks/minio.yml

# Настройка прокси (Nginx)
ansible-playbook -i inventory.ini playbooks/nginx.yml
```

## 🎯 Зачем это нужно (Практическая ценность)

Этот проект — не просто учебная задача «поставить пакет». Он имитирует **реальные сценарии**, с которыми сталкивается системный администратор и DevOps-инженер в продакшене.

### Задание 1. NFS (Файловое хранилище)
**Где это применяется в реальной жизни:**
*   **Централизованное хранение данных.** В компании есть 50 серверов, и всем им нужен доступ к одной папке с логами или бэкапами. Вместо того чтобы копировать файлы по SSH, вы настраиваете NFS, и все серверы видят общую директорию как локальную.
*   **Общие ресурсы для веб-кластера.** Если у вас 5 веб-серверов (Nginx), и пользователи загружают картинки, эти картинки должны быть доступны на всех серверах. NFS решает эту проблему.
*   **Навык:** Понимание разницы между **файловым** (NFS) и **блочным** (iSCSI) доступом, настройка прав и экспортов.

### Задание 2. MinIO (Объектное хранилище)
**Где это применяется в реальной жизни:**
*   **S3-совместимое хранилище (как AWS S3, но локально).** Компании часто не хотят платить за облака (AWS/Google) и разворачивают MinIO на своих серверах. Туда складывают бэкапы, артефакты сборок (Docker-образы), статические сайты.
*   **Отказоустойчивость и масштабирование.** MinIO умеет работать в кластере, распределяя данные по дискам.
*   **Проксирование (Nginx).** В реальной работе MinIO редко «торчит» в интернет напрямую. Обычно перед ним ставят Nginx, который терминирует SSL и проксирует запросы. Это **базовый навык** для любого DevOps.
*   **Навык:** Понимание **объектного** хранилища (бакеты, политики, S3 API) и настройка **реверс-прокси** для доступа к сервису.

**Итог:** Выполнив эти два задания, вы освоите три из четырех типов хранения данных (файловое, блочное, объектное) и научитесь связывать их в единую инфраструктуру.
